# 에코PE 사이즈 설문 — 설치 가이드 (v1.0.1)

GitHub Pages(무료 웹호스팅) + Firebase(무료 데이터 저장)로 돌아가는 설문 사이트입니다.
도메인은 필요 없고, 주소는 `https://내아이디.github.io/ecope-survey/` 형태가 됩니다.

## 파일 구성
| 파일 | 역할 |
|---|---|
| `index.html` | 고객 설문 페이지 (휴대폰 화면 기준) |
| `admin.html` | 관리자 결과 페이지 (구글 로그인, 백분율 그래프, 쿠폰 관리, CSV, QR) |
| `js/config.js` | **설정 파일 — 여기만 고치면 됨** (Firebase 키, 관리자 이메일, 기간, 사이즈 후보, 쿠폰 조건) |
| `firestore.rules` | Firebase 보안 규칙 (콘솔에 붙여넣기) |
| `js/survey.js`, `js/admin.js`, `css/style.css`, `js/vendor/qrcode.js` | 프로그램 본체 (고칠 필요 없음) |

## 1. Firebase 프로젝트 만들기 (10분)
1. https://console.firebase.google.com 접속 → **프로젝트 추가** → 이름 `ecope-survey` → Google 애널리틱스는 **사용 안 함** → 만들기
2. 왼쪽 메뉴 **빌드 → Firestore Database → 데이터베이스 만들기**
   - 위치: **asia-northeast3 (서울)** · 모드: **프로덕션 모드**
3. **규칙** 탭 → 기존 내용을 지우고 `firestore.rules` 전체를 붙여넣기
   - `'관리자이메일@gmail.com'` → 본인 구글 계정으로 변경
   - `timestamp.date(2027, 1, 1)` → 설문 마감일 다음 날로 변경
   - **게시** 클릭
4. **빌드 → Authentication → 시작하기 → 로그인 방법 → Google → 사용 설정 → 저장**
5. **프로젝트 설정(톱니바퀴) → 내 앱 → 웹(</>) 아이콘** → 앱 닉네임 입력 → 등록
   → 나오는 `firebaseConfig` 값들을 `js/config.js` 의 `firebaseConfig` 에 붙여넣기
   (apiKey 는 공개돼도 괜찮은 값입니다. 보안은 3번 규칙이 지킵니다.)
6. `js/config.js` 의 `ADMIN_EMAILS` 도 3번과 같은 이메일로 변경

> 요금: 무료(Spark) 요금제 그대로 쓰면 됩니다. 하루 쓰기 2만 건·읽기 5만 건까지 무료라 설문 용도로는 넉넉하고, 카드 등록을 안 하면 요금이 나올 일이 없습니다.

## 2. GitHub Pages 에 올리기
1. https://github.com 가입/로그인 → 오른쪽 위 **+ → New repository**
   - 이름 `ecope-survey`, **Public**, Create
2. **Add file → Upload files** → 이 폴더의 파일·폴더를 **전부** 끌어다 놓기 → Commit
   (`index.html` 이 맨 위 단계에 있어야 합니다. 폴더째 올려서 한 단계 안으로 들어가지 않게 주의)
3. **Settings → Pages → Branch: main / (root) → Save** → 1~2분 뒤 주소가 표시됨
4. Firebase 콘솔 → **Authentication → 설정 → 승인된 도메인 → 도메인 추가** → `내아이디.github.io` 입력
   (이걸 안 하면 관리자 로그인이 안 됩니다)

## 3. 작동 확인 (꼭 해 보세요)
1. `https://내아이디.github.io/ecope-survey/` → 설문 한 번 제출 (쿠폰 신청 포함)
2. 같은 휴대폰 번호로 한 번 더 → "이미 이 휴대폰 번호로 참여하셨어요"가 나오면 정상
3. `.../admin.html` → 구글 로그인 → 그래프·쿠폰 표에 방금 응답이 보이면 정상
4. 다른 구글 계정으로 로그인 → "관리자가 아니에요"가 나오면 정상
5. 테스트 응답 지우기: Firebase 콘솔 → Firestore → `responses` 에서 문서 삭제
6. (선택) 규칙 점검: Firestore → 규칙 → **규칙 놀이터**에서 `get /responses/아무거나` 를 비로그인으로 실행 → **거부**되면 정상

## 4. 링크 걸기 · QR
- 관리자 페이지 맨 아래 **설문 링크 · QR 코드**에서 경로(상세페이지/택배 박스/톡톡/리뷰)를 고르고 **QR 이미지 받기**
- 경로마다 다른 QR·링크를 쓰면 결과의 **유입 경로**에서 어디서 많이 들어왔는지 보입니다.
- ⚠ **스마트스토어 상세페이지에는 팝업을 띄울 수 없고**(스크립트 불가), 상세페이지·공지사항에 외부 마케팅 링크를 넣는 것은 네이버가 어뷰징으로 제재할 수 있습니다.
  → 상세페이지엔 **QR 이미지 배너**만 넣고, 클릭 링크는 **톡톡 메시지·택배 박스 전단** 위주로 쓰는 것을 권합니다.
  → 쿠폰 대상(누적 30만원 이상) 고객은 장부에서 추려 **톡톡으로 링크를 직접 보내는 것**이 가장 확실합니다.

## 5. 쿠폰 지급 흐름
1. 관리자 페이지 **쿠폰 신청 관리** → 상태 "확인 대기" 목록 확인
2. 장부·주문내역에서 이름/휴대폰으로 **누적 구매 30만원 이상**인지 확인
3. 대상이면 스마트스토어에서 쿠폰 발급 → 상태 **지급 완료**, 아니면 **대상 아님**
4. 처리가 끝나면 **처리 끝난 신청자 개인정보 파기** 버튼 (설문 답변은 남고 이름·번호만 영구 삭제)
   — 화면의 개인정보 안내에 "지급 완료 후 지체 없이, 늦어도 마감 3개월 내 파기"로 적혀 있으니 꼭 지켜 주세요.

## 6. 설정 바꾸기 (js/config.js)
- **기간**: `surveyStart`, `surveyEnd`, `couponEnd` (마감 후엔 자동으로 "마감됐어요" 화면) — 규칙의 `timestamp.date` 도 같이
- **쿠폰 조건**: `couponHistoryAmount`(누적 구매), `couponMinOrder`, `couponDiscount`
- **사이즈 후보**: `SIZE_OPTIONS` — 설문 시작 후에는 `id` 를 바꾸지 마세요 (집계 기준)
- **최대 선택 개수**: `MAX_PICK` (바꾸면 `firestore.rules` 의 `d.sizes.size() <= 2` 도 같이)

## 7. 수정해서 다시 올릴 때 (버전 관리)
1. `js/config.js` 의 `APP_VERSION` 숫자 올리기 (예: 1.0.0 → 1.0.1)
2. `index.html`, `admin.html` 안의 `?v=1.0.0` 도 전부 같은 숫자로 변경 (안 바꾸면 고객 휴대폰에 옛날 파일이 남을 수 있음)
3. GitHub 에서 바뀐 파일만 다시 Upload → 화면 맨 아래 버전 숫자로 반영 확인
- 각 응답에 제출 당시 버전이 저장되어 CSV 에서 확인할 수 있습니다.

## 문제가 생기면
| 증상 | 원인 / 해결 |
|---|---|
| 설문 위에 "[관리자 안내] Firebase 설정이 아직 없습니다" | 1-5단계 `firebaseConfig` 미입력 |
| 버튼이 아무 반응 없음 / "더블클릭해 열면 작동하지 않아요" | PC 파일로 열면 안 됨 → GitHub 주소로 열기 |
| "프로그램 파일을 불러오지 못했어요" | js·css 폴더가 안 올라감 → GitHub에서 폴더 구조 확인 |
| 제출 시 "입력하신 내용을 저장하지 못했어요" | 규칙(1-3) 미게시 또는 마감일 지남 |
| "인터넷 연결이 불안정해…" | 고객 기기에 임시 보관됨 → 다시 보내기 버튼 / 다음 접속·연결 회복 시 자동 재전송 |
| 관리자 로그인 시 "승인 도메인에 없어요" | 2-4단계 승인된 도메인 추가 |
| 로그인은 되는데 "읽기 권한이 없어요" | 규칙의 관리자 이메일과 로그인 계정이 다름 |
| 휴대폰/카톡 안에서 로그인 팝업이 안 뜸 | 자동으로 페이지 이동 방식 로그인으로 전환됨. 그래도 안 되면 크롬·사파리에서 열기 |
